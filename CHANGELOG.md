# Журнал изменений

## 0.2.0

Первый помеченный релиз. Сервер проверен вживую на трёх реальных
конфигурациях (ERP и две отраслевые).

### Что умеет

- **Поиск по метаданным** — объекты, реквизиты, их типы, формы; имена на
  русском и английском (`Справочник` = `Catalog`), без учёта регистра.
- **Код BSL** — поиск процедур по имени, код процедуры, структура модуля,
  полнотекстовый поиск по тексту модулей (запросы, присваивания,
  комментарии).
- **Граф вызовов** — кто вызывает процедуру и что вызывает она, с учётом
  перехватов `&Вместо`/`&После` из расширений. Вызовы общих модулей
  разрешаются по фактам разбора: переменные, реквизиты форм, методы
  менеджеров и платформы не выдаются за вызовы несуществующих модулей.
- **Несколько проектов**, конфигурация и расширения в одном проекте.
- **Фоновая инкрементальная индексация** — переиндексация не блокирует
  клиента, повторный проход перечитывает только изменённые файлы; после
  обновления самого разбора индекс сам переразбирается полностью.
- **Web UI** — проекты, источники, поиск и playground инструментов; работает
  без интернета.
- **MCP** — streamable HTTP (`/mcp`) и SSE для старых клиентов;
  `diagnose_index` показывает качество графа вызовов и причины
  нерезолвленных вызовов.
- Типичный вызов инструмента — доли секунды (`search_procedures` на ERP,
  около 550 тыс. процедур, — 0,1–0,15 с).

### Исправлено в этом цикле

- **MCP и Web UI видят изменения друг друга.** Раньше MCP не замечал
  проекты и источники, добавленные в Web UI после его первого вызова, а
  переиндексация или удаление источника через MCP могли стереть их из
  реестра.
- **Честные ответы вместо ложного успеха:** удаление или переиндексация
  несуществующего источника — ошибка, а не «удалено»/«запущено»;
  `get_call_tree` с `direction`, отличным от `down`/`up`, — ошибка, а не
  тихое «вверх».
- **Поиск по коду говорит, когда выдача неполная:** сработал предел
  просмотра или файлы выгрузки недоступны на сервере — вместо «показано
  всё» и «ничего не найдено».
- **Запросы с пунктуацией** («Справочник.Номенклатура»,
  «ОбщегоНазначения.СообщитьПользователю», «Запрос.Текст =») больше не
  падают с ошибкой полнотекстового поиска.
- **Скорость.** `search_procedures` быстрее примерно в 3,5 раза; в Docker
  на Windows индексы переехали с общей папки `./data` на том Docker —
  поиск процедур 0,1 с вместо 3,5–4,5 с, заработали WAL и блокировки SQLite.
- **Безопасность по умолчанию.** Порты публикуются только на `127.0.0.1`;
  MCP и Web UI отклоняют запросы с чужим заголовком `Host` (защита от DNS
  rebinding).
- **Ошибки инструментов приходят клиенту с `isError: true`** — так же, как
  ошибки в аргументах; текст начинается с `Error executing tool <имя>:`.
- Клиенты MCP видят настоящую версию сервера (раньше в Docker всегда
  было 0.1.0).
- **Пакет устанавливается:** `pip install .` даёт рабочий пакет `src` с
  шаблонами и статикой Web UI и командой `ariadna-index`; нужна Starlette ≥ 1.7
  (в старых Web UI отвечал 400 на разрешённый `Host: [::1]:порт`).

### Обновление с предыдущей сборки

1. `git pull` и `docker compose up -d --build`.
2. **Первый старт дольше обычного.** Сервер один раз переносит индексы из
   `data/projects/*/index.db` на том Docker `ariadna-index` — около 30 с
   на гигабайт индекса. Пока перенос идёт, MCP и Web UI не отвечают. Ход
   переноса, время и размер по каждому проекту — в `docker compose logs`.
3. **Старые `data/projects/*/index.db`** (и `-wal`, `-shm` рядом)
   контейнер больше не читает — после проверки их можно удалить вручную.
4. **Порты теперь только на `127.0.0.1`.** Если к серверу обращаются с
   других машин, запускайте с
   `BIND_ADDR=0.0.0.0 MCP_ALLOWED_HOSTS=<адрес или имя машины>` — иначе
   порты не видны снаружи, а чужой `Host` получает ошибку. Авторизации нет:
   открывайте порты только в доверенной сети.
5. **В настройках агентов замените `localhost` на `127.0.0.1`** — на
   Docker Desktop под Windows каждое соединение к `localhost` стоит около
   0,26 с против ~4 мс.
6. Если прошлая сборка была старше автоматического переразбора, первая
   переиндексация каждого проекта будет полной — это ожидаемо.
