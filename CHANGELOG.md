# Журнал изменений

## Не выпущено

### Новое

- `GET /ready` — готовность проектов отвечать на запросы: `200` — готовы
  все, `503` — хоть один переиндексируется, с ошибкой или не
  проиндексирован; `?project=ID` — один проект. `/health`, как и прежде, —
  только «процесс жив».
- `GET /api/projects/{id}/manifest` — сведения об индексе для внешних
  клиентов: версия Ариадны, источники с версиями конфигураций и временем
  индексации, отпечаток парсера и формат карточек (свой и текущей версии
  сервера), покрытие поисковыми карточками, список того, что требует
  переиндексации.
- `docs/operations.md` — что где лежит, резервная копия, перенос на другую
  машину, восстановление и индекс с нуля.

### Улучшения

- `semantic_search_code` лучше понимает разные формы слов: слова запроса
  ищутся по основе без окончания («заказу» → «заказ»), с беглой гласной
  («скидок» — «скидки») и чередованием «расчет» — «рассчитать». На наборе из
  33 вопросов к крупной конфигурации нужная процедура в первой десятке — в
  94% случаев (было 79%), на первом месте — в 58% (было 48%), MRR 0,70
  (0,58); задержка прежняя. Меняется только разбор запроса —
  переиндексация не нужна.

## 1.1.0

Поиск процедур по описанию своими словами и защита загрузки выгрузок.
Совместимый выпуск: 16 инструментов 1.0 не менялись, добавлен 17-й.

### Обновление с 1.0

Ломающих изменений нет: `git pull` и `docker compose up -d --build`.

- После обновления **переиндексируйте проекты** (`reindex` или кнопка в
  Web UI): в конце переиндексации строятся поисковые карточки процедур —
  один раз, на крупной типовой конфигурации ~5 мин и ~300 МБ индекса;
  дальше — только для изменившихся модулей. Пока карточек нет,
  `semantic_search_code` отвечает ошибкой с советом переиндексировать;
  остальные инструменты работают как прежде.
- Свои копии правил агента дополните по списку «Добавлено в 1.1.0» в
  [docs/agent-rules](docs/agent-rules/README.md). Без своих правил ничего
  делать не нужно — инструкция сервера уже говорит о новом инструменте.
- Если Cursor не показывает новый инструмент — переподключите `ariadna` в
  Settings → MCP.

### Новое

- **`semantic_search_code` — поиск процедур по описанию** («где считается
  себестоимость», «отправить письмо по почте», «курс валюты на дату»). Ищет
  по имени процедуры, объекту и его синониму, области, комментарию и коду;
  разные формы слов совпадают («отправление» — «отправить»); точное имя
  процедуры — первым, у одноимённых — сначала самая вызываемая (исходный
  метод, а не обёртки). Ответ — текст и `structuredContent` по
  опубликованной схеме: фактический режим поиска (`lexical` — по тексту,
  без векторов), свежесть индекса, процедуры с устойчивым `entity_id`,
  путём относительно выгрузки, строками, отпечатком и фрагментом кода,
  постраничная выдача, предупреждения. Решение — `docs/adr/0002-semantic-search-code.md`.

  На наборе из 35 типовых вопросов к крупной конфигурации нужная процедура
  в первой десятке — в 79% случаев (`search_procedures` — 12%), на первом
  месте — в 48% (6%); запрос — 0,2–0,8 с. Замеры и устройство —
  `docs/hybrid-search.md`.
- **Поисковые карточки процедур** — то, по чему ищет новый инструмент:
  подпись, модуль, объект и синоним, область, комментарий, имя, разбитое на
  слова, корни слов и фрагменты тела с номерами строк. Индекс без копии
  текста (полнотекстовый, с ранжированием BM25), строится в конце
  переиндексации только для изменившихся модулей; удаление источника
  удаляет и его карточки.
- **Проверка загружаемых архивов выгрузки.** Пути вне каталога выгрузки,
  абсолютные пути, символические и жёсткие ссылки, устройства отклоняются
  до записи первого файла — раньше tar.gz распаковывался без такой проверки.
  Число файлов и распакованный размер ограничены
  (`ARIADNA_ARCHIVE_MAX_FILES`, по умолчанию 1 млн;
  `ARIADNA_ARCHIVE_MAX_BYTES`, 64 ГБ). Архив распаковывается во временный
  каталог и заменяет `xml/` источника только после успеха: раньше замена
  выгрузки сначала удаляла старую, и битый архив оставлял источник пустым.
- Шаблоны правил агента и README направляют поиск по описанию в
  `semantic_search_code`.

## 1.0.0

Первый стабильный выпуск. Контракт MCP, сложившийся в 0.3.0, проверен
месяцем работы на реальных задачах (Cursor и Claude Code; две крупные
типовые конфигурации и собственная) — замечаний, требующих ломающих изменений, не было.

### Что гарантирует 1.0

В пределах версий 1.x не меняются ломающе:
- имена 16 инструментов MCP, имена и смысл их параметров, умолчания;
- смысл ответов: постраничная выдача (`offset`, строка `use offset=N for
  more`), ошибки как ошибка инструмента (`isError`), оговорки о неполной
  выдаче;
- транспорт — streamable HTTP на `/mcp`, порты по умолчанию (19879 — MCP,
  19878 — Web UI), публикация только на `127.0.0.1`;
- запуск в Docker, расположение данных (`./data`) и индексов (том
  `ariadna-index`).

Новые инструменты, необязательные параметры и уточнения текста ответов
возможны в минорных версиях 1.x. Ломающие изменения — только в 2.0.

### Обновление с 0.3

Ломающих изменений нет: `git pull` и `docker compose up -d --build`.
Первая переиндексация после обновления строит метаданные заново из XML
(см. ниже); сгенерированные раньше `sources/*/report.txt` больше не
читаются, их можно удалить.
Шаблоны правил для агента (ниже) — новые; свои копии правил из 0.3
сверьте с ними.

### Изменения после 0.3.0

- **Шаблоны правил для агента** — [docs/agent-rules](docs/agent-rules/README.md):
  Ариадна как основной индекс конфигурации (`ariadna-primary.mdc`), как
  вспомогательный рядом с другим MCP-сервером (`ariadna-auxiliary.mdc`) и
  блок для встраивания в существующие правила с порядком серверов
  (`ariadna-snippet.md`). Для Cursor, Claude Code и Codex. Имена
  инструментов и параметров в шаблонах сверяются со схемой сервера тестом.
- **Если Ариадна недоступна агенту** — шаблоны правил велят не подменять её
  чтением `projects.json` и файлов выгрузки, а сказать пользователю, что
  сервер не подключён, и как это исправить. В README — почему Cursor,
  запущенный раньше Docker, остаётся без инструментов Ариадны и как его
  переподключить (первое замечание пробной эксплуатации).
- Для разработчика: медленные тесты больше не привязаны к конкретным
  проектам. Какие проекты из локального `data/` переиндексировать, задаёт
  `ARIADNA_CORPUS` (id через запятую: `ARIADNA_CORPUS=demo,myconf python -m
  pytest tests -q -m slow`); проверки общие для любой конфигурации —
  статус, модули и процедуры, метаданные из XML-выгрузки, дерево
  вызовов, поиск. Без переменной тесты пропускаются; проект без
  XML-выгрузки (`Configuration.xml`) — тоже, с понятной причиной, а не
  падением «0 модулей».
- Для разработчика: тестовые фикстуры полностью синтетические. Отчёты по
  конфигурации и XML-выгрузки той же модели собирает
  `tests/fixtures/generate_metadata.py` из выдуманной модели (RU и EN, все
  конструкции формата, которые разбирает сервер), код BSL написан заново
  под те же проверки. Тест
  `test_publication_hygiene.py` следит, чтобы в репозиторий не попадали
  названия прикладных решений.
- **Метаданные — прямо из XML-выгрузки**, своим разбором
  (`src/core/xml_metadata.py`) вместо стороннего генератора отчёта по
  конфигурации (у него не указана лицензия). Промежуточного `report.txt`
  больше нет, extra `xml-report` убран. Результат тот же, что из отчёта,
  и точнее: типы составных реквизитов не теряются, видны критерии
  отбора, формы журналов документов и табличные части задач, а строки
  шаблонов URL, операций веб-сервисов и граф журналов не превращаются в
  лишние объекты. Отчёт Конфигуратора по-прежнему читается — для
  источника без `Configuration.xml` в выгрузке.

## 0.3.0

Подготовка контракта MCP к 1.0. Ломающие изменения — транспорт SSE и имя
параметра модуля, — что сделать при обновлении, см. «Обновление с 0.2».

- **Транспорт SSE убран.** MCP — только streamable HTTP:
  `http://127.0.0.1:19879/mcp`. SSE устарел в спецификации MCP, а все
  поддерживаемые клиенты (Claude Code, Cursor, Codex) работают через
  streamable HTTP. Порт 9877/19877 и переменные `MCP_PORT`, `MCP_HOST_PORT`
  больше не используются.
- **Единое имя параметра модуля — `module_name`.** В `get_procedure_code` и
  `get_module_outline` он назывался `module_path`, в `get_call_tree` —
  `module_name`; теперь везде `module_name` (схема инструментов, инструкция
  сервера, подсказки в ответах, playground Web UI). `module_filter` в
  `search_procedures` и `type_filter` в `search_attributes` — фильтры по
  части имени, они не менялись.
- **Playground Web UI вызывает тот же код, что MCP:** все 16 инструментов
  (добавлены `list_projects`, `list_sources`, `get_procedure_code`,
  `reindex`, `remove_source`), ответы совпадают с тем, что видит агент, —
  включая `offset`, урезание `limit` до 500 и оговорки в ответах.
  Параметры, описания и умолчания формы — из схемы MCP; ошибка инструмента
  выделена. Раньше playground был отдельной реализацией со своим форматом
  и своими умолчаниями.
- **Удаление проекта под нагрузкой MCP:** запрос, заставший удаление, иногда
  получал «Cannot operate on a closed database» вместо обычного «проект
  удалён» — теперь всегда второе.

### Для разработчика

- Web UI и MCP в одном процессе используют один
  `ProjectManager` — общий реестр и пул индексов (`main.build_shared_state`,
  `web/app.py:set_pm`). Механизмы, нужные только нескольким экземплярам в
  процессе, удалены; защита от второго процесса (перечитывание реестра по
  mtime, проверка файла индекса) осталась.
- `scripts/live_check.py` — проверка работающего сервера
  по сети (регрессия, гонки удаления, playground против MCP, стресс); в CI —
  Docker-образ целиком на Linux и запуск без Docker на Windows.
- При запуске без Docker на Windows шум ProactorEventLoop
  (`ConnectionResetError [WinError 10054]` из `_call_connection_lost`, когда
  клиент резко закрыл соединение) понижен с ERROR до DEBUG; другие ошибки
  asyncio не затронуты.

### Обновление с 0.2

- **Клиенты, подключённые через SSE** (`http://…:19877/sse`), —
  переподключить на streamable HTTP:
  - Claude Code:
    `claude mcp remove --scope user ariadna` и
    `claude mcp add --transport http --scope user ariadna http://127.0.0.1:19879/mcp`;
  - Cursor (`.cursor/mcp.json` или `~/.cursor/mcp.json`):
    `"ariadna": { "url": "http://127.0.0.1:19879/mcp" }`;
  - Codex CLI: `codex mcp remove ariadna` и
    `codex mcp add ariadna --url http://127.0.0.1:19879/mcp`
    (или `url = "http://127.0.0.1:19879/mcp"` в `[mcp_servers.ariadna]`
    `~/.codex/config.toml`).

  Если в `.env` или в команде `docker compose` задан `MCP_HOST_PORT` — его
  можно убрать, он больше ни на что не влияет.
- **`module_path` → `module_name`** в вызовах `get_procedure_code` и
  `get_module_outline` (скрипты, сохранённые промпты). Синонима нет: SDK MCP
  отбрасывает неизвестные аргументы до обработчика, и вызов со старым именем
  получает ошибку «module_name: Field required». Агентам ничего делать не
  нужно — они читают схему при подключении.

## 0.2.1

Исправления после 0.2.0.

- **Лог без лишних трассировок:** запрос к SSE (`/sse`) с чужим `Host` или
  `Origin` по-прежнему получает 421/403, но в логе теперь одна строка
  предупреждения, а не полная трассировка на каждый такой запрос.
- **`python -m src.core.indexer <проект>`** индексирует проект без сервера и
  без установки пакета (раньше молча ничего не делал) — то же, что
  `ariadna-index`. Не запускайте параллельно с работающим сервером.
- **Удаление во время переиндексации** источника или проекта больше не
  оставляет в индексе обрывки: пока идёт прогон, удаление отклоняется
  (MCP — ошибка с подсказкой, Web UI — 409), повторите после завершения.
- **`get_procedure_code` предупреждает,** если файл модуля изменили после
  индексации (например, обновили выгрузку, а переиндексацию не запускали):
  границы процедуры могут быть неверны, нужен reindex.
- **Ответы не разрастаются:** `limit` больше 500 урезается (об этом пишется в
  конце ответа, дальше — через `offset`); `diagnose_index` показывает первые
  100 пропущенных процедур и «показано N из M».
- **`search_code`:** одна строка кода — одна запись в выдаче (раньше
  несколько вхождений на строке давали дубли); оговорка «выдача ограничена»
  называет предел, который действительно сработал.
- **Надёжнее при одновременной работе Web UI и MCP:** правки реестра
  проектов больше не затирают друг друга, первое обращение к проекту из
  нескольких потоков не теряет соединение с базой; на Windows запись
  `projects.json` не падает, если файл в этот момент читается.
- **`get_index_status` больше не сообщает о готовности до окончания
  переиндексации:** раньше он отвечал `ready` сразу после метаданных, пока
  код BSL ещё разбирался (на крупной конфигурации — минуты), и не показывал прогресс. Сразу
  после ответа `reindex` статус тоже уже `indexing` — раньше в первые доли
  секунды он ещё показывал прежний `ready`.
- **Сервер больше не отвечает «проект не найден», пока записывается реестр
  проектов** (на Docker Desktop под Windows `projects.json` на `/data`
  заменяется не атомарно).
- **После закрытия индекса на Windows не остаются открытые файлы** —
  удаление проекта и очистка временных каталогов больше не падают.
- **После удаления и повторного создания проекта с тем же id MCP больше не
  отдаёт данные удалённого индекса.**
- **Удаление проекта при запуске без Docker на Windows больше не падает,
  пока MCP держит индекс открытым.**
- **Удаление проекта под нагрузкой больше не оставляет пустой файл
  индекса** — и не роняет сервер, если MCP в этот момент ищет по проекту.
- **Запрос к проекту, который удаляют в этот момент, получает понятное
  «проект удалён»** без лишних ошибок в логе.
- **Docker — поддерживаемый способ запуска сервера; запуск без Docker
  описан как режим разработки.** Без Docker серверы теперь слушают только
  `127.0.0.1` (`LISTEN_ADDR`), а не все интерфейсы.
- Зависимости перечислены в одном месте — `pyproject.toml`; Docker-образ и
  скрипт скачивания колёс берут их оттуда.
- Для разработчика: медленные тесты (`-m slow`) ничего не пишут в `data/` —
  корпус только читается, реестр и индексы во временном каталоге;
  контейнер на время прогона останавливать не нужно.

### Обновление

1. **Новая команда обновления колёс** для офлайн-сборки образа — из корня
   репозитория (на Windows — только из PowerShell, с полным путём вместо
   `$PWD`):

   ```bash
   docker run --rm -v "$PWD:/repo" -w /repo python:3.12-slim sh docker-wheels/fetch.sh
   ```

   Старые колёса заменяются новыми целиком, при сбое сети прежний набор
   остаётся. Затем `docker compose up -d --build`.
2. **Тесты требуют окружение, как в `pyproject.toml`:** в чужом (например,
   глобальный Python со старыми Starlette и mcp) сессия сразу прерывается со
   списком неподходящих пакетов. Соберите `.venv`:
   `python -m venv .venv`, активируйте, `pip install -e ".[dev]"`.

## 0.2.0

Первый помеченный релиз. Сервер проверен вживую на трёх реальных
конфигурациях (одна крупная типовая и две отраслевые).

### Что умеет

- **Поиск по метаданным** — объекты, реквизиты, их типы, формы; имена на
  русском и английском (`Справочник` = `Catalog`), без учёта регистра.
- **Код BSL** — поиск процедур по имени, код процедуры, структура модуля,
  полнотекстовый поиск по тексту модулей (запросы, присваивания,
  комментарии).
- **Граф вызовов** — кто вызывает процедуру и что вызывает она, с учётом
  перехватов `&Вместо`/`&После` из расширений. Вызовы общих модулей
  разрешаются по фактам разбора: переменные, реквизиты форм, методы
  менеджеров и платформы не выдаются за вызовы несуществующих модулей.
- **Несколько проектов**, конфигурация и расширения в одном проекте.
- **Фоновая инкрементальная индексация** — переиндексация не блокирует
  клиента, повторный проход перечитывает только изменённые файлы; после
  обновления самого разбора индекс сам переразбирается полностью.
- **Web UI** — проекты, источники, поиск и playground инструментов; работает
  без интернета.
- **MCP** — streamable HTTP (`/mcp`) и SSE для старых клиентов;
  `diagnose_index` показывает качество графа вызовов и причины
  нерезолвленных вызовов.
- Типичный вызов инструмента — доли секунды (`search_procedures` на крупной
  конфигурации, около 550 тыс. процедур, — 0,1–0,15 с).

### Исправлено в этом цикле

- **MCP и Web UI видят изменения друг друга.** Раньше MCP не замечал
  проекты и источники, добавленные в Web UI после его первого вызова, а
  переиндексация или удаление источника через MCP могли стереть их из
  реестра.
- **Честные ответы вместо ложного успеха:** удаление или переиндексация
  несуществующего источника — ошибка, а не «удалено»/«запущено»;
  `get_call_tree` с `direction`, отличным от `down`/`up`, — ошибка, а не
  тихое «вверх».
- **Поиск по коду говорит, когда выдача неполная:** сработал предел
  просмотра или файлы выгрузки недоступны на сервере — вместо «показано
  всё» и «ничего не найдено».
- **Запросы с пунктуацией** («Справочник.Номенклатура»,
  «ОбщегоНазначения.СообщитьПользователю», «Запрос.Текст =») больше не
  падают с ошибкой полнотекстового поиска.
- **Скорость.** `search_procedures` быстрее примерно в 3,5 раза; в Docker
  на Windows индексы переехали с общей папки `./data` на том Docker —
  поиск процедур 0,1 с вместо 3,5–4,5 с, заработали WAL и блокировки SQLite.
- **Безопасность по умолчанию.** Порты публикуются только на `127.0.0.1`;
  MCP и Web UI отклоняют запросы с чужим заголовком `Host` (защита от DNS
  rebinding).
- **Ошибки инструментов приходят клиенту с `isError: true`** — так же, как
  ошибки в аргументах; текст начинается с `Error executing tool <имя>:`.
- Клиенты MCP видят настоящую версию сервера (раньше в Docker всегда
  было 0.1.0).
- **Пакет устанавливается:** `pip install .` даёт рабочий пакет `src` с
  шаблонами и статикой Web UI и командой `ariadna-index`; нужна Starlette ≥ 1.7
  (в старых Web UI отвечал 400 на разрешённый `Host: [::1]:порт`).

### Обновление с предыдущей сборки

1. `git pull` и `docker compose up -d --build`.
2. **Первый старт дольше обычного.** Сервер один раз переносит индексы из
   `data/projects/*/index.db` на том Docker `ariadna-index` — около 30 с
   на гигабайт индекса. Пока перенос идёт, MCP и Web UI не отвечают. Ход
   переноса, время и размер по каждому проекту — в `docker compose logs`.
3. **Старые `data/projects/*/index.db`** (и `-wal`, `-shm` рядом)
   контейнер больше не читает — после проверки их можно удалить вручную.
4. **Порты теперь только на `127.0.0.1`.** Если к серверу обращаются с
   других машин, запускайте с
   `BIND_ADDR=0.0.0.0 MCP_ALLOWED_HOSTS=<адрес или имя машины>` — иначе
   порты не видны снаружи, а чужой `Host` получает ошибку. Авторизации нет:
   открывайте порты только в доверенной сети.
5. **В настройках агентов замените `localhost` на `127.0.0.1`** — на
   Docker Desktop под Windows каждое соединение к `localhost` стоит около
   0,26 с против ~4 мс.
6. Если прошлая сборка была старше автоматического переразбора, первая
   переиндексация каждого проекта будет полной — это ожидаемо.
