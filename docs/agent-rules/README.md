# Правила для агента: как пользоваться Ариадной

При подключении Ариадна сама передаёт агенту инструкцию — какой инструмент
для какого вопроса. Но в проекте 1С обычно уже есть свои правила (Cursor
rules, `AGENTS.md`, `CLAUDE.md`) и другие MCP-серверы со своим порядком
вызовов. Без явного правила агент не знает, кого из них спрашивать первым, а
одинаковые имена инструментов (`search_code`, `search_metadata`) у разных
серверов путают его ещё больше. Шаблоны здесь закрывают это.

| Файл | Когда |
|---|---|
| [`ariadna-primary.mdc`](ariadna-primary.mdc) | Ариадна — **основной** индекс конфигурации; другие серверы — для того, чего в ней нет (смысловой поиск, формы, шаблоны, БСП, документация) |
| [`ariadna-auxiliary.mdc`](ariadna-auxiliary.mdc) | Основной индекс — **другой** сервер; Ариадна — когда он не помог, для точных вопросов по коду и вызовам и для сверки |
| [`ariadna-snippet.md`](ariadna-snippet.md) | В проекте **уже есть** правило с порядком серверов — вставить блок прямо в него, без отдельного файла |

## Как выбрать

- Других серверов индекса конфигурации нет, или Ариадна отвечает лучше
  них — `ariadna-primary.mdc`.
- Есть основной сервер, которому доверяете, и Ариадна нужна в помощь —
  `ariadna-auxiliary.mdc`.
- Правила уже устроены цепочкой «сервер 1 → сервер 2 → Grep» — вариант A
  (Ариадна первой) или B (перед Grep) из `ariadna-snippet.md`. Два правила с
  разным порядком серверов противоречат друг другу; одна цепочка — нет.

## Что подставить

- `<project_id>` — id проекта в Ариадне (`list_projects` или Web UI). Один
  репозиторий — один проект Ариадны; конфигурация и её расширения — источники
  этого проекта.
- `<описание проекта>` — одна строка: какая конфигурация и расширения.
- `<основной сервер>` (только `ariadna-auxiliary.mdc`) — имя MCP-сервера,
  которое агент видит в списке серверов.

Остальное менять не обязательно. Если в ваших правилах принят другой язык
или стиль — перепишите, но сохраните имена инструментов и параметров как
есть: они проверяются тестом на совпадение со схемой сервера
(`tests/test_agent_rules.py`).

## Куда положить

- **Cursor** — файл `.mdc` в `.cursor/rules/` репозитория проекта 1С
  (`alwaysApply: true` — правило короткое и нужно при любом вопросе о
  конфигурации). Блок из `ariadna-snippet.md` — в существующее правило с
  порядком серверов.
- **Claude Code** — текст без заголовка `---` в `CLAUDE.md` проекта (или в
  файл, на который он ссылается).
- **Codex CLI** и другие агенты, читающие `AGENTS.md`, — туда же.

Подключение самого сервера к агенту — в [README](../../README.md), раздел
«Подключение MCP к агенту».

## Версии

Шаблоны соответствуют текущей версии сервера (имена инструментов и
параметров из этого репозитория). После обновления Ариадны сверьте свои
копии с этими файлами — изменения имён описываются в
[CHANGELOG](../../CHANGELOG.md), в разделах «Обновление с …».
