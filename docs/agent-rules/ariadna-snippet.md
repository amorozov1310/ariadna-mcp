# Ариадна — блок для встраивания в существующие правила

Для проектов, где уже есть правило с порядком MCP-серверов (например,
«сначала индекс конфигурации, потом Grep»). Вместо отдельного файла правил —
вставить один из вариантов в это правило, рядом с остальными серверами, и
подставить `<project_id>`.

## Вариант A — Ариадна первой (шаг 0 цепочки)

Вставить в начало списка «какие серверы вызывать по порядку»:

> 0. `ariadna` (проект `<project_id>`) — для объектов, реквизитов, процедур,
>    кода и вызовов: `search_metadata(query)` → `get_object_details(full_name)`,
>    `search_attributes(query, type_filter)`, `find_references(object_name)`,
>    `search_procedures(query)` → `get_procedure_code(module_name, procedure_name)`,
>    `get_module_outline(module_name)`,
>    `get_call_tree(procedure_name, module_name, direction)`,
>    `search_code(query, file_pattern)`. Смысловой поиск по описанию — не здесь:
>    в Ариадне полнотекстовый поиск без семантики.

## Вариант B — Ариадна перед Grep (последний MCP-шаг)

Вставить последним шагом перед переходом к Grep / Glob:

> N. `ariadna` (проект `<project_id>`) — если предыдущие серверы не дали
>    нужного: код процедуры с номерами строк — `get_procedure_code(module_name, procedure_name)`,
>    кто вызывает / что вызывает — `get_call_tree(procedure_name, module_name, direction)`,
>    где объект используется как тип — `find_references(object_name)`,
>    текст в коде — `search_code(query, file_pattern)`.

## В таблицу «что вызывать для какой задачи»

Если в правиле есть таблица задач, добавить к нужным строкам столбец или
пометку «`ariadna`: …» с инструментом из списков выше. Не дублировать в ней
правила чтения ответов — их достаточно один раз (см. раздел «Как читать
ответы» в `ariadna-primary.mdc`), например отдельным коротким правилом.

## Общее для обоих вариантов

- `project_id="<project_id>"` во всех вызовах, кроме `list_projects`.
- Одинаковые имена инструментов у разных серверов (`search_code`,
  `search_metadata`) — указывать сервер: «`search_code` сервера `ariadna`».
- `reindex` — только с согласия пользователя; `remove_source` — никогда без его
  прямой просьбы.
- Сервера `ariadna` нет в списке инструментов или он не отвечает — не
  подменять его чтением `projects.json` или файлов выгрузки: сказать
  пользователю, что Ариадна не подключена (проверить
  `http://127.0.0.1:19878/health` и переподключить MCP-сервер в клиенте), и
  идти по цепочке дальше без неё.
