# ADR 0003. Локальный доступ без лицензии

Статус — принято. Этап 3a.

## Контекст

Ариадна бесплатна при локальной работе. Для доступа с других машин нужен
ключ для этой версии, который сервер проверяет офлайн. При нативном запуске
оба сервера по умолчанию слушают `127.0.0.1`. В контейнере оба слушают
`0.0.0.0`, иначе Docker не сможет пробросить порты. Compose по умолчанию
публикует их на `127.0.0.1` хоста. Когда публикация шире, запросы через
порт хоста, в том числе от его браузера, могут прийти с адреса одного шлюза
Docker. По IP клиента внутри контейнера нельзя надёжно различить эти запросы.

## Решение

- При нативном запуске оба сервера выбирают один адрес. Без действующего
  ключа непетлевой `LISTEN_ADDR` заменяется на `127.0.0.1`, о чём сообщают
  лог и Web UI. Петлевой IP, в том числе `::1`, применяется сразу. С ключом
  применяется заданный адрес. Для смены привязки нужен перезапуск.
- Точка входа Docker запускает серверы в режиме контейнера, где необходима
  широкая привязка. Публикацию портов на хосте контролирует Docker. Для
  бесплатного режима в Compose следует оставить `BIND_ADDR=127.0.0.1`.
- Одна ASGI-прослойка на Web UI и MCP проверяет HTTP-запросы до маршрутизации
  и авторизации. Без действующего ключа принимается один заголовок `Host`
  с `127.0.0.1`, `localhost` или `[::1]`, с портом от 1 до 65535 или без порта.
  Ответ на другой `Host` объясняет, как установить ключ или оставить доступ
  локальным. Для Web UI сохраняется HTTP 400, для MCP — HTTP 421.
- После установки ключа вступают в силу обычные настройки `MCP_ALLOWED_HOSTS`
  и проверка `Origin` в MCP SDK. Изменения файла ключа подхватываются без
  перезапуска. При удалении ключа, неверной подписи или слишком новой версии
  сервера ограничение применяется снова со следующего запроса. Кэш сверяет
  хеш содержимого ключа при каждой проверке. На нативном сервере, запущенном
  с широкой привязкой при действующем ключе, новые запросы через непетлевой
  интерфейс отклоняются даже с петлевым `Host` до восстановления лицензии.
  Перезапуск без ключа освобождает широкий сокет. Уже открытый поток MCP
  не прерывается. Контракт инструментов MCP 1.x сохраняется.
- Маршруты используют общую проверку, включая статику, вход и диагностику.
  Docker healthcheck обращается к `/health` с `Host: localhost:9878`.
  Для `/ready` подходит тот же локальный адрес с сохранением правил
  авторизации. В этой версии маршрут проверки процесса называется `/health`.

## Границы проверки

В Docker привязка `BIND_ADDR` к loopback ограничивает сетевую доступность.
Если оператор публикует порты на `0.0.0.0`, проверка `Host` отбивает обычное
обращение по сетевому адресу или имени. Клиент по-прежнему может подставить
петлевой `Host` вручную. Прокси, который передаёт петлевой `Host`, также может
дать внешний доступ к бесплатной установке, даже если сам сервер слушает
только loopback. Для доступа из сети нужен действующий ключ.
Проверка лицензии подтверждает подлинность ключа. Она также доступна для
изменения оператором, который контролирует исходный код или образ. Сборка
через Nuitka отложена. Она усложнит изменение кода, а подстановка `Host`
при широкой публикации портов останется возможной.

Поэтому для бесплатной установки порты следует публиковать только на
loopback и не выставлять их через прокси. Для сети нужны действующий
ключ, открытые порты, разрешённые имена и настроенные токены доступа.
