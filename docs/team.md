# Командный сервер: личные токены и роли

Одна Ариадна на сервере в сети — для всей команды: один индекс, один словарь,
агенты всех разработчиков подключаются к ней. Чтобы сервер не был открыт
каждому, кто достаёт до портов, у каждого человека (и робота) — свой токен.

Пока не создан ни один токен, Ариадна работает как раньше, без входа: локальной
установке ничего настраивать не нужно.

Один токен (администратора) — бесплатно: так можно закрыть свой сервер.
Сетевой доступ и токены для коллег и роботов доступны по лицензионному ключу,
[docs/license.md](license.md).

## 1. Открыть сервер для других машин

По умолчанию порты публикуются только на `127.0.0.1`. Установите ключ через
Web UI на самом сервере и создайте первый токен по инструкции ниже. Затем
откройте доступ из сети:

```bash
BIND_ADDR=0.0.0.0 MCP_ALLOWED_HOSTS=192.168.1.10,ariadna.lan docker compose up -d
```

`MCP_ALLOWED_HOSTS` — имена и адреса, под которыми к серверу обращаются (защита
от DNS rebinding, см. README, «Сервер на другой машине»).

## 2. Первый токен — администратора

В Web UI: меню справа в шапке (значок шестерёнки) → «Доступ и токены»
(`http://127.0.0.1:19878/admin/tokens` на сервере) → «Включить вход по токенам…». Экран
перечислит последствия и как восстановить доступ, если токен потеряется; после
«Включить вход и создать токен» первый токен получает роль администратора, и вы
сразу входите с ним; с этого момента вход обязателен. Новый токен показывается
один раз — с кнопкой «Копировать» и готовой настройкой агента под «Как
подключить агента». Следующие токены — кнопка «Выдать токен» на той же странице.

Или из командной строки на сервере, в каталоге с `docker-compose.yml`:

```bash
docker compose exec ariadna python -m src.auth create --name "Иван Петров" --role admin
```

Там же: `python -m src.auth list` — список токенов, `python -m src.auth revoke <id>` —
отозвать. Запущенный сервер подхватывает изменения сам, перезапуск не нужен.

Токен показывается **один раз** — сохраните его. На диске (`data/tokens.json`)
хранится только его хеш.

## 3. Токены для команды

Нужен лицензионный ключ ([license.md](license.md)): в нём указано, сколько
токенов можно выдать. Администратор устанавливает его на странице «Лицензия»
и создаёт токены на странице «Доступ и токены» (обе — в меню справа в шапке) — по одному на
человека и на робота (например, скрипт выгрузки), с ролью:

| Роль | Может |
|---|---|
| `user` (участник) | поиск, все инструменты чтения, проверка вызовов, «Доработки», обновление индекса, словарь |
| `admin` (администратор) | всё, что `user`, плюс создание и удаление проектов, их состав (конфигурация и расширения), настройки проектов, токены |

Токен ушедшего сотрудника — «Отозвать»: остальные продолжают работать.

## 4. Подключить агента с токеном

Токен передаётся в заголовке `Authorization: Bearer <токен>`.

**Claude Code:**

```bash
claude mcp add --transport http --scope user ariadna http://ariadna.lan:19879/mcp --header "Authorization: Bearer ar_..."
```

или в `.mcp.json` проекта — так токен не попадёт в репозиторий, он берётся из
переменной окружения `ARIADNA_TOKEN` (задайте её у себя в системе). Имя
переменной — любое, кроме служебных вроде `ANTHROPIC_API_KEY` или `NPM_TOKEN`:
такие Claude Code в заголовках подставляет пустыми.

```json
{
  "mcpServers": {
    "ariadna": {
      "type": "http",
      "url": "http://ariadna.lan:19879/mcp",
      "headers": { "Authorization": "Bearer ${ARIADNA_TOKEN}" }
    }
  }
}
```

**Cursor** — `.cursor/mcp.json`, токен из той же переменной окружения
(у Cursor подстановка пишется `${env:ИМЯ}`):

```json
{
  "mcpServers": {
    "ariadna": {
      "url": "http://ariadna.lan:19879/mcp",
      "headers": { "Authorization": "Bearer ${env:ARIADNA_TOKEN}" }
    }
  }
}
```

Переменную окружения задайте до запуска редактора (в Windows — «Переменные
среды» или `setx ARIADNA_TOKEN ar_...` и перезапуск Cursor): `.env`-файлы для
удалённых серверов Cursor не читает.

Другие клиенты MCP — так же: заголовок `Authorization` в настройках
HTTP-сервера. Скрипты и API Web UI — тот же заголовок:

```bash
curl -X POST -H "Authorization: Bearer ar_..." http://ariadna.lan:19878/api/projects/myconf/reindex
```

В Web UI каждый входит со своим токеном на странице «Вход».

## Безопасность

- Ариадна отдаёт HTTP без шифрования: в сети токен виден так же, как запросы и
  ответы. В доверенной офисной сети этого достаточно; иначе поставьте перед
  ней обратный прокси с HTTPS (nginx, Caddy) и откройте наружу только его.
- Потерянный токен — отозвать и выдать новый.
- Сбросить авторизацию полностью (например, потерян токен единственного
  администратора): остановить сервер и удалить `data/tokens.json` — Ариадна
  снова открыта без входа, первый новый токен станет администраторским.

## Регулярное обновление индекса

Робот выгрузки (скрипт по расписанию) обновляет индекс со своим токеном роли
`user` — [docs/update.md](update.md). Это тоже токен из лицензии.
