# Гибридный поиск: карточки, замеры, решения

Рабочий документ шагов развития после 1.0 (см.
[ADR 0001](adr/0001-standalone-1x.md)). Здесь — то, что уже сделано и
измерено, и то, что из этого следует для следующих шагов.

## Карточка процедуры

`src/core/cards.py` строит карточку детерминированно, из индекса и файла
модуля, без LLM:

- **заголовок** — директива и подпись процедуры, модуль, объект метаданных
  и его синоним, область (`#Область`, вложенные через `/`), комментарий
  сразу над объявлением;
- **фрагменты тела** — строки процедуры подряд, каждый не длиннее
  `CHUNK_CHARS` (1500) символов, с номерами строк; хвост длинной процедуры
  уходит в следующие фрагменты, ничего не отбрасывается;
- **текст для индексации** — заголовок + фрагмент (по тексту на фрагмент);
- **`content_hash`** — отпечаток формата карточки (`CARD_FORMAT`), заголовка
  и тела: меняется код процедуры или синоним объекта — меняется отпечаток;
  код соседних процедур на него не влияет.

Файл модуля недоступен — карточка остаётся с одним заголовком
(`body_available=False`), процедура не пропадает.

Посмотреть карточки и замерить их на своём индексе:

```bash
python -m src.core.cards --project ID --show 3
docker exec ariadna python -m src.core.cards --project ID   # индекс в контейнере
```

## Замер карточек на реальных индексах

2026-10-30, контейнер Ариадны 1.0 на рабочей машине разработчика,
`CHUNK_CHARS=1500`. Конфигурации обезличены.

| Конфигурация | Карточек (процедур) | Фрагментов | С комментарием | Символов тел | Сборка |
|---|---:|---:|---:|---:|---:|
| Малая отраслевая | 701 | 829 | 4% | 0,5 млн | 0,8 с |
| Средняя с 11 расширениями | 4 348 | 5 082 | 16% | 2,9 млн | 3 с |
| Крупная типовая А | 543 060 | 754 362 | 13% | 572 млн | 130 с |
| Крупная типовая Б | 549 266 | 797 749 | 15% | 632 млн | 149 с |

Распределение на крупных: фрагментов на карточку в среднем 1,4 (p95 — 3,
максимум — 873 у одной процедуры); символов во фрагменте p50 ≈ 600,
p95 ≈ 1490; заголовок p50 ≈ 300, p95 ≈ 550 символов.

## Что из этого следует

- **Объём векторов.** ~800 тыс. фрагментов на крупную конфигурацию:
  при 384 измерениях это ~1,2 ГБ во float32 и ~0,3 ГБ в int8 на проект.
  Хранить на диске, в память — не всё сразу.
- **Время эмбеддингов — главный риск.** Первичный расчёт ~800 тыс.
  фрагментов по ~600–2000 символов на CPU займёт, по грубой оценке, часы.
  Измерить на шаге выбора модели; варианты сокращения — индексировать
  сначала экспортные процедуры и модули объектов, пересчитывать только
  изменившиеся по `content_hash`, фоновая очередь с приоритетом.
- **Комментарии редки** (4–16% процедур) — смысл в основном приходится
  извлекать из имён, синонимов объектов, областей и кода; ценность
  заголовка карточки выше, чем самих комментариев.
- **Лексическая ветка по карточкам.** Тексты тел — 0,6 млрд символов на
  крупную конфигурацию; дублировать их в обычной FTS-таблице нельзя.
  Шаг 4: contentless FTS5 по текстам карточек (как `module_text_fts`, но
  на уровне фрагмента и с BM25-рангом) и замер размера.
- **Сборка карточек** — ~2,5 мин на крупную конфигурацию за один проход;
  приемлемо как часть переиндексации, если делать её по изменившимся
  модулям.
