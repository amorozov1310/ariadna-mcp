# Лицензия командного режима

| | Бесплатно | Команда (по ключу) |
|---|---|---|
| Поиск, граф вызовов, проверки, «Отличия», словарь, все инструменты MCP | да | да |
| Один токен администратора — закрыть свой сервер | да | да |
| Личные токены для коллег и роботов выгрузки, роли `admin` / `user` | — | да, сколько указано в ключе |
| Регулярное обновление индекса из базы ([update.md](update.md)) | да, со своим токеном | да, у робота — свой токен |

Ключ **бессрочный**: он работает со всеми версиями Ариадны, вышедшими до даты
«обновления до» включительно (обычно — год с покупки). Более новая версия с
этим ключом работает в бесплатном режиме, пока ключ не продлён; прежняя версия
с ним работает всегда.

Ариадна проверяет ключ сама, без интернета: никуда не обращается и ничего не
отправляет.

## Установить ключ

В Web UI: «Лицензия» (ссылка в шапке у администратора; пока токенов нет —
`http://<сервер>:19878/admin/license`) → выбрать файл ключа или вставить его
текст → «Установить ключ». На странице видно, на кого выдан ключ, на сколько
пользователей, до какой даты обновления и сколько токенов уже занято.

Или из командной строки на сервере, в каталоге с `docker-compose.yml`
(файл ключа — в `data/`, контейнер видит его как `/data/…`):

```bash
docker compose exec ariadna python -m src.license install /data/ariadna.key
docker compose exec ariadna python -m src.license show
```

Ключ хранится в `data/license.key`; запущенный сервер подхватывает его сам,
перезапуск не нужен.

## Что происходит без ключа

- Можно создать **один** токен (он всегда администраторский) — сервер
  закрыт от посторонних, работает один человек.
- Второй токен не создаётся: Web UI и `python -m src.auth create` объясняют,
  что нужен ключ.
- Если токенов больше, чем разрешено (ключ удалён, не подходит к этой версии
  или в нём меньше пользователей), работают первые разрешённые токены —
  администраторы в первую очередь, затем по дате создания; остальные получают
  ответ 403 с объяснением. Ничего не удаляется: после установки или продления
  ключа все токены снова работают.

## Выпуск ключей (для владельца Ариадны)

Ключи подписываются закрытым ключом Ed25519, который есть только у владельца;
в Ариадну встроен парный открытый ключ (`PUBLIC_KEY` в `src/license.py`).

**Один раз** — пара ключей (уже создана; повторять только при утере):

```bash
python -m src.license keygen --out ~/.ariadna-license
```

Закрытый ключ (`ariadna_license_private.pem`) — **никогда в репозиторий**;
сделайте резервную копию в надёжном месте. Утерян — новые ключи не выпустить,
придётся сменить `PUBLIC_KEY` и перевыпустить ключи всем клиентам.

**Ключ клиенту** — после оплаты:

```bash
python -m src.license issue --private-key ~/.ariadna-license/ariadna_license_private.pem --owner "ООО Ромашка" --users 10 --updates-until 2027-11-07 --out romashka.key
```

`romashka.key` — отправить клиенту. Проверить перед отправкой:
`python -m src.license show romashka.key`. Продление — тот же `issue` с новой
датой `--updates-until`; расширение — с новым `--users`.

Функция `issue()` из `src/license.py` годится и для автоматической выдачи
(сервис по уведомлению об оплате) — закрытый ключ тогда живёт только на нём.

При каждом выпуске версии в `src/RELEASE_DATE` ставится дата выпуска: с ней
сравнивается «обновления до».

Проверка ключа — защита от случайного нарушения условий, а не от взлома:
основная защита — договор с клиентом.
