# Лицензия сетевого доступа и командного режима

Условия использования Ариадны описаны в [лицензионном соглашении](../LICENSE).
Текст соглашения доступен и в Web UI на странице «Лицензия».

| | Бесплатно | Команда (по ключу) |
|---|---|---|
| Поиск, вызовы, проверка вызовов, «Доработки», словарь, все инструменты MCP | да | да |
| Доступ к Web UI и MCP с других машин | — | да |
| Один токен администратора — закрыть свой сервер | да | да |
| Личные токены для коллег и роботов выгрузки, роли `admin` / `user` | — | да, сколько указано в ключе |
| Регулярное обновление индекса из базы ([update.md](update.md)) | да, со своим токеном | да, у робота — свой токен |

Ключ **бессрочный**: он работает со всеми версиями Ариадны, вышедшими до даты
«обновления до» включительно (обычно — год с покупки). Более новая версия с
этим ключом работает в бесплатном режиме, пока ключ не продлён; прежняя версия
с ним работает всегда.

Ариадна проверяет ключ сама, без интернета: никуда не обращается и ничего не
отправляет.

## Установить ключ

В Web UI: «Лицензия» в меню справа в шапке (значок шестерёнки; на сервере
со входом — имя администратора) → выбрать файл ключа или вставить его
текст → «Установить ключ». Вверху страницы — сводка: действует ли ключ, на
кого выдан, на сколько пользователей, до какой даты обновления и сколько
токенов уже занято. При действующем ключе форма свёрнута под «Заменить ключ».

Или из командной строки на сервере, в каталоге с `docker-compose.yml`
(файл ключа — в `data/`, контейнер видит его как `/data/…`):

```bash
docker compose exec ariadna python -m src.license install /data/ariadna.key
docker compose exec ariadna python -m src.license show
```

Ключ хранится в `data/license.key`. Запущенный сервер подхватывает изменения
ключа на следующем запросе. Для изменения адреса, на котором слушает
нативный сервер, перезапустите его с нужным `LISTEN_ADDR`.

## Что происходит без ключа

- При нативном запуске Web UI и MCP слушают петлевой IP. Если в `LISTEN_ADDR`
  задан другой адрес, оба сервера слушают `127.0.0.1`.
- Web UI и MCP принимают только петлевой `Host`: `127.0.0.1`, `localhost`
  или `[::1]` (с портом от 1 до 65535 или без порта). То же ограничение
  действует, если ключ повреждён, удалён или не подходит к версии сервера.
  Для установки ключа через Web UI откройте «Лицензия» на самом сервере.
- Можно создать **один** токен (он всегда администраторский) — сервер
  закрыт от посторонних, работает один человек.
- Второй токен не создаётся: Web UI и `python -m src.auth create` объясняют,
  что нужен ключ.
- Если токенов больше, чем разрешено (ключ удалён, не подходит к этой версии
  или в нём меньше пользователей), работают первые разрешённые токены —
  администраторы в первую очередь, затем по дате создания; остальные получают
  ответ 403 с объяснением. Ничего не удаляется: после установки или продления
  ключа все токены снова работают.

В Docker сетевую границу задаёт публикация портов на хосте. Для бесплатного
режима оставьте `BIND_ADDR=127.0.0.1` и не выставляйте порты через прокси.
При `BIND_ADDR=0.0.0.0` проверка `Host` отбивает случайный доступ по сетевому
имени или адресу. Сетевой клиент может пройти её, подставив петлевой `Host`
вручную или обратившись через прокси, который передаёт такой `Host`.
Для сетевого доступа установите действующий ключ. Подробности в [ADR 0003](adr/0003-free-mode-local-only.md).

## Выпуск ключей (для владельца Ариадны)

Ключи подписываются закрытым ключом Ed25519, который есть только у владельца;
в Ариадну встроен парный открытый ключ (`PUBLIC_KEY` в `src/license.py`).

**Один раз** — пара ключей (уже создана; повторять только при утере):

```bash
python -m src.license keygen --out ~/.ariadna-license
```

Закрытый ключ (`ariadna_license_private.pem`) — **никогда в репозиторий**;
сделайте резервную копию в надёжном месте. Утерян — новые ключи не выпустить,
придётся сменить `PUBLIC_KEY` и перевыпустить ключи всем клиентам.

**Ключ клиенту** — после оплаты, в утилите выдачи (из корня репозитория):

```bash
python -m tools.license_desk
```

Откроется `http://127.0.0.1:9890` (только на этом компьютере):

- список клиентов с поиском и датой окончания обновлений у каждого;
- «Новый клиент и ключ»: организация, контактное лицо, email, телефон,
  заметка, число пользователей, «обновления до» (по умолчанию — год) и
  основание (счёт, договор) → «Выпустить ключ»;
- после выпуска — «Скачать файл ключа» и готовый текст письма: скопировать
  или открыть в почтовой программе (файл прикладывается вручную);
- карточка клиента — правка контактов, история выданных ключей (каждый можно
  скачать снова) и продление: новый ключ на год от конца прежних обновлений.

Реестр (`registry.json`) и выданные ключи (`keys/<номер>.key`) хранятся в
том же каталоге `~/.ariadna-license`, что и закрытый ключ, — включите его в
резервную копию целиком. Другой каталог — `--home` или переменная
`ARIADNA_LICENSE_HOME`.

То же из командной строки, без реестра:

```bash
python -m src.license issue --private-key ~/.ariadna-license/ariadna_license_private.pem --owner "ООО Ромашка" --users 10 --updates-until 2027-11-07 --out romashka.key
```

`romashka.key` — отправить клиенту. Проверить перед отправкой:
`python -m src.license show romashka.key`. Продление — тот же `issue` с новой
датой `--updates-until`; расширение — с новым `--users`.

Функция `issue()` из `src/license.py` годится и для автоматической выдачи
(сервис по уведомлению об оплате) — закрытый ключ тогда живёт только на нём.

При каждом выпуске версии в `src/RELEASE_DATE` ставится дата выпуска: с ней
сравнивается «обновления до».

Проверка ключа — защита от случайного нарушения условий, а не от взлома:
основная защита — договор с клиентом.
